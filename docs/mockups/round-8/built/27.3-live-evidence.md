# 27.3: the street map on the live demo server (evidence)

Dylan ran the map command (`docs/runbooks.md`, "The street map") from his phone on 2026-11-03,
then the server-files refresh in the same section. The server itself can't be read from this repo,
so this records what the live site answers. Checked from the build session, through the demo's own
password (HTTP basic auth only).

## The file is there, about 740 MB, and served from `/maps/`

2026-11-03T15:45:39Z, `curl -r 0-6 https://acme.staffingresourcingtest.uk/maps/uk.pmtiles`:

```
HTTP/2 206
content-range: bytes 0-6/739874121
content-length: 7
```

The first 7 bytes read `PMTiles` (the format's magic). 739,874,121 bytes is the zoom-13 UK
extract's size measured from the build's index before it was made (`docs/logs/work-2026-11.md`, "The
street map is live on the demo"). Caddy serves `/maps/*` from `/opt/shiftdesk/maps`
(`deploy/Caddyfile`), so the file is `/opt/shiftdesk/maps/uk.pmtiles`.

## `MAP_TILES_URL` is set

The dashboard passes `appEnv().MAP_TILES_URL` to the map (`src/app/office/page.tsx:50`), and the
map draws streets only with it (`src/app/office/dashboard/venue-map.tsx`: `data-venue-map` is
`"streets"` with a file, `"plain"` without). On the live dashboard, logged in as the demo's admin:

- Laptop, 1280px: `data-venue-map="streets"`, MapLibre's canvas, tiles answered 206, no console
  errors: `27.3-live-street-map-laptop.png`.
- Phone, 390px (2026-11-03, 14:08 London): `data-venue-map="streets"`, one canvas, the pins and
  "© OpenStreetMap contributors", no page errors, nothing sideways: `27.3-live-street-map-phone.png`.

With `MAP_TILES_URL` empty the page says `data-venue-map="plain"` and draws no canvas, as it did on
the live site before the command (the launch review's §4).
